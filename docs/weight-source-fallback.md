# 权重回退与每日来源

当 `SOURCE_PROVIDER=aizhan` 时，顺序为：爱站 Agent → master 复测 → 站长之家；未配置 Agent 时为爱站 master → 站长之家。爱站成功立即保存；失败才请求站长权重，无需付费 API 或新增密钥。

明确限流/封禁仍遵守对应站点冷却，不会切换节点继续请求被封禁的爱站。爱站冷却不阻塞可用的站长，站长冷却也不阻塞可用的爱站；都不可用时遵循原有有限重试策略。普通超时、HTTP 400、空响应或解析不完整只影响当前任务，403/429、明确验证码或 Retry-After 才触发来源冷却。

站长权重回退与站长补充任务共享请求间隔、请求并发（单请求）和冷却状态，但独立排队和保存。APPPC 排名、分类、注册人、邮箱、到期日仍由原有补充任务负责。

## 数据字段

每日 `domain_daily_metrics` 快照新增：

| 字段 | 含义 |
| --- | --- |
| `weight_source` | `aizhan` / `chinaz`，本条权重实际来源 |
| `weight_valid` | `true`：权重有效；`false`：本次刷新失败或权重不完整；缺失：历史数据无法校验 |

`source_url`、`raw_sha256`、`collected_at` 记录权重响应，`supplemental_*` 单独记录补充资料。成功后替换本日整组权重，不混用两站字段。真实零值保留，缺失值不补零。刷新失败保留旧数值供查看，但标记为不可比较；后续成功恢复有效状态。补充资料失败不影响权重有效性。

启动后在后台自动补标历史数据，不阻塞健康检查，无需清库或重新执行 Mongo 初始化，仍可使用 `SKIP_MONGO_INIT=1`。原始 URL 和有效的百度 PC/移动权重用于识别旧来源，同日最新主采集任务成功才确认旧数据有效。来源不明、任务记录已清理的历史数据不猜测、不发通知。迁移可重复执行；超时仅记录警告，保留已处理部分，后续启动继续处理。

## 通知与页面

`weight_change_notifier.py` 只比较目标日与前一自然日。两天权重有效且来源相同才比较各字段：15 日站长、16 日爱站跳过；两天都是站长可以比较。任意一天失败、缺失或来源不明跳过，不向更早日期寻找基准。单项缺失不视为零。

前端列表显示快照日期和来源，趋势弹窗列出每日来源、PC/移动权重及状态。不同来源、无效日和缺失日之间不连线。CSV 导出包含来源和状态。

## 升级

1. 更新并重启后端。启动日志含 `weight source fields ready`，成功任务日志含 `weight_source`。
2. 更新并构建 `seo_monitor_web` 前端。
3. **同步更新实际运行的权重通知脚本，并重启其进程/定时服务。** 本仓库现在包含该脚本；若服务器通知程序在其他目录，需要更新那个文件。仅更新 Go 服务不会改变旧通知进程。

使用原有通知环境文件验证，不发送 Webhook：

```sh
python3 /usr/local/seo_monitor/weight_change_notifier.py \
  --env-file /path/to/existing-weight-alert.env --once --dry-run
```

日志显示已比较、缺少快照、来源或有效性不符的数量。旧失败域名可使用原有单域名强制采集入口重试；补标历史来源无需重新全量采集。
